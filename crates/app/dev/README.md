# Dev data

`worst_case.jsonl` is **synthetic** dev data, not a real recording: a hand-built Claude Code session in the same `{"dir","msg"}` line format as `crates/core/tests/fixtures/`, filled with the worst realistic content a session produces (a long heredoc Bash command, a long MCP tool name, a write to a deeply nested path, a 2,000-line tool output, a failing tool, CJK and emoji, a long code block, and two approvals queued at once). Use it to stress-test the UI with the fake claude: `mkdir -p /tmp/newjen-worst/Developer/clients/northwind-industries-holdings/platform-monorepo/services/billing-reconciliation`, then run `NEWJEN_CLAUDE=target/debug/newjen-fake-claude NEWJEN_FAKE_FIXTURE=crates/app/dev/worst_case.jsonl cargo run -p app -- <that dir>`, type any prompt and press Enter, then answer the four approvals in order with ⌘↵, ⌘↵, ⌘↵ and Esc (the fake exits with code 3 if an answer doesn't match). The last line keeps the fake waiting for another prompt, like the real CLI, so the finished turn shows Done instead of an exit error. It is not used by any test.
